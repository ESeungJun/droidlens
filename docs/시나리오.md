# 시나리오

사용자가 원래 하려던 일을 끝까지 할 수 있는지 보는 흐름 목록이에요. [기획서](기획서.md)의 "핵심 시나리오"와 "문서로 QA 돌리기" 흐름에서 뽑았어요.
- 단계는 [기능 지도](기능지도.md)의 ID(`F3` …)로 적어요. 지도의 시나리오 칸에도 같은 SC ID 를 적어요.
- 릴리스 전에는 P0 전부와 이번에 더하거나 바꾼 시나리오를 실제 빌드에서 돌려요(`scenario-review`).
- 확인 스크립트가 있는 시나리오는 스크립트부터 돌리고, 없는 것만 손으로 해요(아래 "확인 방법").

| ID | 누가, 무엇을 | 시작 상태 | 단계 | 기대 결과 | 우선 |
|---|---|---|---|---|---|
| SC-01 | 개발자가 남의 앱 구조 보기 | 기기 연결, SDK 없는 아무 앱 설치 | 1. F14 기기 고르기 → 2. F9 라이브러리 → 3. F2 뷰 계층 3D → 4. F3 화면 흐름 자동 탐색 | 라이브러리·난독화 추정, 3D 계층, 화면 지도가 나옴. 실패 길: 결제·삭제·로그아웃·전송 버튼은 자동 탐색이 누르지 않고 건너뜀 | P1 |
| SC-02 | 개발자가 내 앱 네트워크·데이터 보기 | SDK 를 넣은 debug 빌드(샘플 앱) 설치 | 1. F5 네트워크에서 요청 보기 → 2. F5 목 규칙으로 실패 응답 → 3. F7 Prefs·DB 보기·고치기 | 요청·응답이 보이고, 목을 켜면 앱이 실패 응답을 받고, 고친 Prefs 가 앱에 반영됨. 실패 길: SDK 없는 앱이면 "DroidLens SDK 필요" 안내가 보임 | P1 |
| SC-03 | Claude Code 사용자가 말로 시나리오 검증 | MCP 등록·에이전트 설치, 기기 연결 | 1. F15 `droidlens-verifier` 에 시나리오 말하기 → 2. F10 단계별 판정·캡처 → 3. 통과면 F11 스크립트 저장 | HTML 리포트가 남고, 통과한 흐름은 `~/.droidlens/scripts/` 에 YAML 로 저장됨. 실패 길: 화면에 없는 요소면 막힘·실패로 남고 스크립트는 저장되지 않음 | P0 |
| SC-04 | CI·터미널에서 회귀 실행 | 저장된 스크립트, 기기 연결, 샘플 앱 설치 | 1. F11 `droidlens-mcp run <파일>` (`--junit`·`--summary`) | 통과면 종료 코드 0 과 JUnit·요약 파일. 실패 길: 없는 요소를 기다리는 스크립트는 종료 코드 1 | P0 |
| SC-05 | 처음 쓰는 사람이 기기 연결 | 기기·에뮬레이터 없음 | 1. F14 기기 연결 도우미 → 2. AVD 만들기·실행(또는 USB 디버깅 안내) | 부팅이 끝나면 기기가 골라지고 화면이 보임. 실패 길: adb 를 못 찾으면 "설정에서 adb 연결하기" 안내로 F13 에서 경로를 고름 | P1 |
| SC-06 | QA 담당이 기획서로 QA 회차 돌리기 | 샘플 앱 설치, `examples/qa` 의 기획서·TC 표 | 1. F18(또는 F16 `droidlens-qa-planner`)에 문서 넣기 → 2. TC 뽑기 → 3. 추적표로 검토·고르기 → 4. 실행 → 5. 결과표 → 6. F10 회차 묶음에서 엑셀·단계별 HTML 내보내기 | 요구사항 7개가 모두 TC 로 덮이고, 고른 TC 의 회차 결과표(HTML·CSV·JUnit)와 엑셀·단계별 HTML 이 나옴. 실패 길: 덮이지 않은 요구사항은 검토 화면에 표시되고, 실패한 TC 는 결과표에 실패로 남음 | P0 |
| SC-07 | 누구든 확인 필수 버튼을 실수로 누르지 않기 | 결제·삭제·전송 같은 버튼이 있는 화면 | 1. F15 `tap`·`script_run` 으로 그 버튼 누르기 시도 → 2. F16 확인 필수 TC 실행 | 사람이 허용하기 전에는 누르지 않고 막힘으로 남음. 허용은 앱 화면이나 터미널 `qa allow` 에서만 | P0 |

|---|---|
| SC-03 | 손(에이전트 실행이 필요). `droidlens-verifier` 로 샘플 앱 "메모 추가" 흐름을 시킨 뒤 리포트와 저장된 스크립트를 확인해요 |
| SC-04 | `bash scripts/verify/F11-script-run.sh <캡처 폴더>` |
| SC-06 | `node scripts/verify/F16-qa-example.mjs <캡처 폴더>` (기기 없이 문서 넣기 → 검토까지만: `--no-device`, CI 에서 돌아요). TC 뽑기와 첫 실행은 에이전트가 하는 일이라 스크립트는 같은 결과를 내는 정해진 코드로 대신해요. 에이전트로 뽑는 것은 손으로 확인해요 |
| SC-07 | 단위 시험 `packages/mcp/test/qa.test.mjs`·`packages/mcp/test/tools.test.mjs`(`docs/RULES.md` 8번)와 손 |
| 나머지 | 손 |
