# droidlens 개선안

점검 기준: `master` c298283 (v0.11.0), 2026-11-10. 저장소 파일은 고치지 않았다.

## 한 줄 정의

안드로이드 개발자·QA 가 adb 만으로 기기의 아무 앱이나 들여다보고(미러링·뷰 계층·화면 지도·라이브러리), Claude Code 에이전트에게 MCP 도구로 같은 기기를 조작·검증시키는 데스크톱 도구. 아카이브된 Flipper 의 자리를 노린다.

## 컨셉·의도

- 출처: `README.ko.md`, `docs/기획서.md`, `docs/ROADMAP.md`.
- 목표 네 가지(`docs/기획서.md` "목표"): SDK 없이 어떤 앱이든 본다 / 사람이 아니라 에이전트가 직접 쓰고 검증한다 / 안드로이드 개발자가 아니어도 시작한다 / 혼자서도 굴러간다(릴리스만 올리면 설치·업데이트).
- 대상: Android 개발자, QA, Claude Code 사용자.
- 핵심 가치: 에이전트가 말로 받은 시나리오를 실제 기기에서 돌리고, 통과한 흐름이 YAML 회귀 스크립트로 남는다(`packages/mcp/src/tools/scenario.ts:248-259`).
- 배포: GitHub Releases(mac arm64/x64 서명·공증, Windows, Linux AppImage), 한 줄 설치 스크립트, 앱 안 업데이트(SHA256SUMS 대조), SDK 는 JitPack, MCP 단독 파일 `droidlens-mcp.mjs`. MIT. 수익 모델 없음.

## 구조와 스택

- pnpm 모노레포. `packages/core`(adb 엔진, TS, 의존 6개) ← `packages/mcp`(MCP SDK 1.32, esbuild 단일 번들 1.5MB) / `apps/desktop`(Electron 44 + React 19 + xyflow, core 를 번들에 포함).
- 의존 방향은 한쪽이다. core 는 mcp·desktop 을 모른다. desktop 은 mcp 번들을 `extraResources` 로 싣는다(`apps/desktop/electron-builder.yml`).
- `android/agent`: Instrumentation + UiAutomation, `localabstract:droidlens_agent` 에 자체 HTTP 서버. `android/sdk`·`sdk-noop`: 앱에 넣는 라이브러리, `localabstract:droidlens_sdk_<패키지>`.
- 흐름: 호스트 → `adb forward tcp:0 localabstract:…` → `fetch http://127.0.0.1:<포트>` (`packages/core/src/http.ts:18`). 기기 쪽은 접속 UID 가 shell(2000)·root 인지 본다.
- adb 호출은 전부 `execFile`(호스트 셸 없음, `packages/core/src/adb.ts:60-76`). 기기 셸로 가는 문자열은 `assertPackage`·`quoteShell`·숫자 반올림으로 막는다.
- 산출물은 `~/.droidlens/`. 상태 저장은 파일(JSON 원자적 쓰기 `workspace.ts:37-46`).
- CI: `ci.yml`(빌드·테스트·gradle·데스크톱 빌드), `release.yml`(태그 → 5종 설치 파일 + 체크섬), `commit-convention.yml`.

### 🔴 1. `wait_for` 가 에이전트 없이는 항상 시간 초과로 끝난다 (v0.11.0 회귀)

- **지금 문제**: `packages/mcp/src/tools/input.ts:164` 가 `dl.quickDump(dev)` 를 쓴다. `quickDump` 는 이 프로세스에 캐시된 에이전트 연결이 있을 때만 덤프하고 없으면 `undefined` 다(`packages/core/src/hierarchy.ts:118-126`, `agent.ts:123-126`). `undefined` 면 루프가 그냥 500ms 를 자고 돈다(`input.ts:165-175`). 그래서 `DROIDLENS_AGENT=0`(README 가 안내하는 설정), APK 를 못 찾은 MCP 단독 실행, Appium 과 충돌해 에이전트가 내려간 60초(`agent.ts:190`), 서버를 띄우고 첫 호출이 `wait_for` 인 경우에 요소가 화면에 있어도 "나타나지 않음"으로 던진다. `gone=true` 도 같다. 스크립트 러너의 `wait` 는 `dumpHierarchy` 를 써서 멀쩡하다(`packages/core/src/script.ts:754`). 바로 위 주석(`input.ts:163`)과 들여쓰기가 `focusedField` 것을 복사한 흔적이고, `git log -S` 로 보면 v0.11.0 릴리스 커밋(fe36f1d)에서 들어왔다. `agents/droidlens-verifier.md:31` 은 화면 전환마다 `wait_for` 를 쓰라고 한다.
- **고치는 방법**: `input.ts:164` 를 `await dl.dumpHierarchy(dev).catch(() => undefined)` 로 바꾼다. 화면 전환 중 일시 오류는 다음 바퀴에서 다시 본다. 시간 초과 메시지에 마지막으로 본 화면의 Activity 와 비슷한 텍스트 후보 3개를 붙인다.
- **나아지는 점**: 에이전트를 끈 환경·MCP 단독 환경에서 검증 흐름이 돌아간다. 실패 메시지가 다음 행동(셀렉터 고치기)을 알려 준다.
- **예상 결과**: 에이전트 없이 `wait_for(text=…)` 가 1.5~3초(uiautomator 한 번) 안에 "발견"을 돌려준다. 회귀 시험은 `quickdump-proof.test.mjs` 를 `packages/mcp` 쪽 시험으로 옮기면 된다(가짜 `DeviceAdb` 로 `wait_for` 핸들러 호출).

### 🟠 3. 포워딩된 로컬 포트에 요청 검사가 없다

- **지금 문제**: SDK 서버와 에이전트 서버는 기기 쪽 접속 UID 만 본다(`SdkServer.java:93-98`, `AgentServer.java:54-58`). `adb forward` 로 열린 호스트 `127.0.0.1:<임의 포트>` 로 들어온 요청은 전부 shell UID 로 보이므로 통과한다. 요청의 `Host`·`Origin` 헤더나 토큰은 보지 않는다(`SdkServer.java:128-183`, `AgentServer.java:67-137`). 그래서 브라우저에 열린 웹 페이지가 포트를 훑어 `POST /db/query?db=…&write=1`(본문이 SQL, `SdkServer.java:210`), `POST /mocks/set`(앱을 다시 시작해도 남는 응답 바꿔치기), `POST /text`(포커스된 입력칸에 글자 주입) 를 단순 요청으로 보낼 수 있고, DNS 리바인딩이면 `/prefs`·`/network/detail` 응답도 읽는다. 같은 PC 의 다른 프로세스는 어차피 adb 를 직접 쓸 수 있으니 새 위험이 아니다. 늘어나는 것은 브라우저 경유다. 최근 브라우저의 로컬 네트워크 차단 정책에서 실제로 성립하는지는 확인 못 했다.
- **고치는 방법**: 두 서버의 `handle` 맨 앞에 세 가지를 넣는다. (1) `Host` 가 `127.0.0.1:*`·`localhost:*` 가 아니면 403. (2) `Origin` 헤더가 있으면 403. (3) `X-DroidLens: 1` 헤더가 없으면 403(브라우저는 이 헤더를 붙이려면 사전 요청이 필요하고 서버는 `OPTIONS` 에 답하지 않는다). 호스트 쪽은 `packages/core/src/http.ts:18` 의 `fetch` 에 헤더 한 줄. 에이전트는 `AGENT_VERSION` 을 5 로 올린다.
- **나아지는 점**: 디버그 앱의 DB·Prefs·목과 기기 입력이 웹 페이지에서 닿지 않는다.
- **예상 결과**: `curl http://127.0.0.1:<포트>/prefs` 가 403, DroidLens 는 그대로 동작. 예전 SDK(헤더를 안 보는 버전)와도 호환된다(헤더를 더 보내는 것뿐).

### 🟠 4. 앱 안 대화창이 되돌릴 수 없는 도구까지 확인 없이 허용한다

- **지금 문제**: `apps/desktop/src/main/chat.ts:178-179` 가 헤드리스 실행에 `--allowedTools mcp__droidlens__*` 를 준다. `clear_app_data`(`app.ts:60-72`), `db_query(write=true)`(`sdk.ts:126-142`), `prefs_set`·`prefs_remove`, `open_deeplink`(임의 URI) 가 묻지 않고 실행된다. 막는 것은 에이전트 지침 문장뿐이다(`agents/droidlens-verifier.md` 원칙 3). 에이전트는 앱 화면의 글자를 읽으므로(`view_hierarchy`) 화면에 심긴 지시에 노출된다. 저장소도 이 위험을 알고 있다(`graph.ts:90-93`, `scenario.ts:38-40` 주석).
- **고치는 방법**: MCP 서버에 `DROIDLENS_CONFIRM=1` 환경 변수를 두고, 켜져 있으면 `clear_app_data`·`db_query(write)`·`open_deeplink`(http/https 가 아닌 스킴) 가 실행 전에 MCP elicitation 으로 묻거나, 지원하지 않는 클라이언트면 "사용자 확인 필요"로 거부한다. `chat.ts:134` 의 `env` 에 이 값을 넣고, 데스크톱은 대화창에 확인 버튼을 띄운다. 최소안은 `chat.ts:162` 인자에 `--disallowedTools mcp__droidlens__clear_app_data` 추가.
- **나아지는 점**: 대화창에서 데이터 삭제·DB 쓰기는 사람이 한 번 누른 뒤에만 일어난다.
- **예상 결과**: 대화창에서 "앱 데이터 지워줘" → 확인 버튼 → 실행. 화면 글자로 유도된 호출은 버튼에서 멈춘다.

### 🟠 5. SDK 가 디버그 빌드인지 스스로 확인하지 않는다

- **지금 문제**: `DroidLensInitProvider.java:12` → `DroidLens.init`(`DroidLens.java:38-57`) 이 조건 없이 서버를 연다. `android/` 전체에 `FLAG_DEBUGGABLE` 검사가 없다(grep 0건). release 누출을 막는 것은 사용자가 `debugImplementation`/`releaseImplementation` 을 나눠 적는 것뿐이다. `implementation` 으로 잘못 넣으면 릴리스 앱이 Prefs·DB·네트워크 기록을 adb 에 열고, 네트워크 목도 릴리스에서 적용된다. 릴리스 앱은 원래 `run-as` 가 안 되므로 USB 디버깅만으로는 못 보던 데이터다.
- **고치는 방법**: `DroidLens.init` 첫 줄에서 `(context.getApplicationInfo().flags & ApplicationInfo.FLAG_DEBUGGABLE) == 0` 이면 `Log.w` 한 줄 남기고 반환. 일부러 켜려는 경우를 위해 `DroidLens.allowNonDebuggable()` 을 둔다. `MockStore.load` 도 같은 조건 뒤로.
- **나아지는 점**: 의존성 설정 실수 한 번이 릴리스 데이터 노출로 이어지지 않는다.
- **예상 결과**: `android/sample` 을 `implementation project(':sdk')` 로 바꿔 release 빌드해도 `/proc/net/unix` 에 `droidlens_sdk_` 소켓이 없다.

### 🟠 6. 스크린샷 좌표와 `tap` 좌표의 배율이 다르고 알려 주지 않는다

- **지금 문제**: `screenshot` 은 긴 변 900px 로 줄인 JPEG 를 돌려준다(`packages/mcp/src/common.ts:25-31`, `packages/core/src/image.ts:8-12`). 응답 글은 `saved: <경로>` 뿐이다(`tools/device.ts:29-33`). `tap` 의 `x`·`y` 는 기기 픽셀인데 인자 설명이 없다(`input.ts:16-17`). 1080×2400 기기면 이미지에서 읽은 좌표가 2.67배 어긋난다. `screenshot_compare` 의 차이 이미지(`screen.ts:97`)도 같다.
- **고치는 방법**: `imageContent` 가 `{ width, height, scale }` 를 같이 돌려주게 하고, `screenshot` 응답에 `원본 1080x2400 · 이미지 405x900 · tap 좌표 = 이미지 좌표 × 2.667` 한 줄을 넣는다. `tap.x/y`, `swipe.x1…` 에 `.describe('기기 픽셀 (view_hierarchy 의 @bounds 와 같은 좌표계)')`.
- **나아지는 점**: 셀렉터가 안 잡히는 화면(WebView·Flutter·게임, README "알려진 한계")에서 좌표 탭이 맞는다.
- **예상 결과**: 스크린샷만 보고 누르는 경우의 헛탭이 사라진다.

## 기능 기획 제안

### 1. 조작 응답에 "그 뒤 화면" 요약을 붙인다 — M

- **무엇**: `tap`·`type_text`·`swipe`·`press_key`·`open_deeplink` 가 입력 후 화면이 멈출 때까지 기다리고, 응답에 `Activity 변화`, `새로 보이는 글자 상위 8개`, `사라진 글자`, `크래시 여부`, `대상 앱이 앞에 있는지`를 3~6줄로 붙인다. `observe: false` 로 끈다.
- **왜 맞나**: 목표 2("에이전트가 직접 쓰고 검증")의 왕복 수를 줄인다. 지금은 `tap` → `wait_for` → `view_hierarchy` 세 번이다. Flipper·Android Studio 에는 없는 축이다.
- **흐름**: 에이전트가 `tap(text="로그인")` → 응답 `tapped … → LoginActivity → HomeActivity. 새로 보임: "안녕하세요", "주문 내역" …`.
- **범위**: 새 `packages/core/src/observe.ts`(전후 `Hierarchy` 의 글자 집합 차이, `waitForSettle` 재사용 `graph.ts:66-99`), `packages/mcp/src/tools/input.ts` 의 응답 조립. 에이전트가 없으면 uiautomator 로 1.5~3초가 더 걸리므로 그때는 기본을 끈다.

### 2. `install_apk` 와 "고치고 다시 검증" 고리 — S

- **무엇**: MCP 에 `install_apk(path, grantPermissions?)` 를 추가한다(지금 50개 도구에 설치가 없다). `script_run` 에 `apk` 인자를 주면 설치 → 실행 → 결과를 한 번에.
- **왜 맞나**: Claude Code 가 코드를 고친 뒤 `./gradlew assembleDebug` 는 스스로 돌릴 수 있다. 설치만 MCP 밖(`adb install`)이라 기기 선택·오류 처리가 끊긴다. 수정 → 설치 → 저장된 스크립트 재실행이 한 흐름이 된다.
- **흐름**: "장바구니 버그 고쳐줘" → 코드 수정 → 빌드 → `install_apk` → `script_run("장바구니")` → 리포트.
- **범위**: `packages/core/src/app.ts` 에 `installApk`(`agent.ts:106-115` 의 설치·서명 불일치 처리와 같은 방식), `packages/mcp/src/tools/app.ts`. 경로는 `guardPath` 와 같은 규칙으로 cwd 안의 `.apk` 만.

### 3. 스크립트 변수와 비밀값 주입 — M

- **무엇**: YAML 에 `${env.TEST_ID}`·`${vars.keyword}` 를 허용하고, 녹화할 때 비밀로 보이는 입력(`typedLabel` 이 가리는 경우, `input.ts:186-192`)은 값 대신 `${env.DROIDLENS_SECRET_1}` 로 저장하고 이름을 알려 준다.
- **왜 맞나**: 지금은 `type_text` 로 넣은 비밀번호가 `~/.droidlens/scripts/*.yaml` 에 그대로 남는다(`input.ts:184` 주석이 인정). 회귀 스크립트를 저장소에 넣거나 CI 에서 돌리려면 필요하다. ROADMAP 3단계 미완료 항목("스크립트 매개변수 주입")이기도 하다.
- **흐름**: 검증 통과 → 저장된 YAML 에 `type: { text: "${env.DROIDLENS_SECRET_1}" }` → CI 에서 환경 변수로 주입 → `droidlens-mcp run`.
- **범위**: `packages/core/src/script.ts` 의 `loadScript`·`runStep`(치환, 없는 변수면 실행 전 오류), `packages/mcp/src/tools/input.ts`(녹화 시 치환), CLI `--var k=v`(`packages/mcp/src/index.ts:27-47`).

### 4. CI 용 출력: JUnit XML 과 PR 요약 — S

- **무엇**: `droidlens-mcp run <폴더> --junit out.xml --summary out.md`. 요약에는 실패 단계와 스크린샷 경로. 예시 워크플로(에뮬레이터 + 실행)를 `examples/` 에.
- **왜 맞나**: 완료 기준 "CLI 로 돌려 CI 에서 종료 코드로 받는다"는 이미 된다. 지금은 콘솔 글과 로컬 HTML 뿐이라(`index.ts:33-46`) PR 에 붙지 않는다. 에이전트가 만든 스크립트가 PR 검사로 이어지는 마지막 한 칸이다.
- **범위**: `packages/core/src/script.ts` 의 `runSuite` 결과 → 새 `report-junit.ts`, `packages/mcp/src/index.ts` 인자 2개, `examples/ci/android-emulator.yml`.

### 5. 재현 묶음(repro bundle) — M

- **무엇**: `scenario_finish(verdict=fail)` 이나 새 도구 `repro_bundle` 이 한 폴더에 단계별 스크린샷, 실패 시점 뷰 계층, 그 구간 logcat·크래시, SDK 가 있으면 네트워크 기록(가려진 채), 기기·앱 버전, 재현 YAML, `ISSUE.md`(기대/실제/재현 순서)를 모은다.
- **왜 맞나**: 검증 에이전트가 찾은 것을 고치는 에이전트(또는 사람)에게 넘기는 단위가 생긴다. Flipper 는 사람이 보는 도구라 이 단계가 없다.
- **흐름**: verifier 가 실패 → `~/.droidlens/scenarios/<id>/repro/` → Claude Code 에 "이 폴더 보고 고쳐줘".

## 성능 제안

- **`current_screen`·`scenario_step` 의 Fragment 조회를 선택으로**: `dumpsys activity top` 이 1~7초(`packages/core/src/app.ts:23` 주석, `:48` 타임아웃 10초). `screen.ts:19`, `scenario.ts:191` 이 매번 켠다. 단계가 10개인 시나리오면 10~70초가 여기서 나간다. 기본을 끄고 필요할 때만.
- **`wait_for` 폴링**: 500ms 마다 전체 덤프(`input.ts:162-176`). 에이전트가 있으면 `agent.waitIdle`(`agent.ts:77-79`)로 접근성 이벤트가 잠잠해질 때만 덤프하면 덤프 횟수가 준다. `waitForSettle` 이 이미 그렇게 한다(`graph.ts:73-76`).
- **스냅샷 모드**: `handle('screenshot')` 이 원본 PNG 를 base64 문자열로 IPC 에 싣는다(`apps/desktop/src/main/index.ts:85`). 1080×2400 이면 약 2MB → 2.7MB 문자열을 250ms 주기(`ScreenTab.tsx:69`)로 보낸다. `downscaleToJpeg`(실측 76~94ms, 234KB)를 거쳐 `Uint8Array` 로 보내면 전송량이 1/10 이다. 뷰 계층 탭의 정밀 스크린샷은 원본 유지.
- **미러링 패킷 경로**: `scrcpy.ts:137` 이 청크마다 `Buffer.concat` 으로 전체를 다시 복사하고 `:159` 에서 패킷을 한 번 더 복사한 뒤 IPC 로 보낸다(`main/index.ts:142`). 8Mbps·60fps 에서 체감 문제를 확인하지는 못했다. 고친다면 읽기 위치만 옮기는 링 버퍼. 우선순위 낮음.
- **측정해 보니 문제없던 것**: MCP 스크린샷 축소(동기 실행 76~94ms), 렌더러 번들 1.36MB(로컬 파일 로드).

## 확인 못 한 것

- **기기 연결 동작 전부**: 기기·에뮬레이터를 붙이지 않았다. 🔴 1번은 코드 경로와 `quickDump` 단위 재현으로만 확인했고 실제 `wait_for` 호출은 돌리지 않았다. 미러링 fps, 덤프 시간(README 의 0.03~0.3초), 탐색 속도는 재지 않았다.
- **android gradle 빌드**(`./gradlew :agent:assembleRelease :sdk:assembleRelease …`): 돌리지 않았다. 자바 소스는 읽기만 했다.
- **🟠 3번의 브라우저 경유 공격**: 실제 브라우저에서 시도하지 않았다. 브라우저별 로컬 네트워크 접근 정책에 따라 막힐 수 있다.
- **JitPack 실제 배포 상태**: `v0.11.0` 태그의 `sdk` 아티팩트가 빌드돼 있는지 외부 조회를 하지 않았다.
- **Windows·Linux 동작**, 앱 안 업데이트의 실제 교체 과정, 서명·공증 결과.
- **데스크톱 UI 실물**: 앱을 띄우지 않았다. 디자인 절은 README 스크린샷(구 버전 탭 구조)과 소스 기준이다.
- **`DroidLensInterceptor.java`(413줄)·`NetworkStore`·`Redactor` 의 세부 규칙**: 구조와 목 적용 지점만 봤고 가리기 규칙의 누락 사례는 따져 보지 않았다.
- **점검 중 생긴 부수 효과**: `pnpm install` 의 `prepare` 스크립트가 `git config core.hooksPath .githooks` 를 실행했다(저장소 `.git/config`, 추적 파일 아님). 원래 값이 무엇이었는지는 모른다. `git status` 는 깨끗하다. 빌드 산출물(`packages/*/dist`, `apps/desktop/out`, `node_modules`)은 무시 대상이라 남겨 뒀다.
- **사용자가 정할 것**: (1) 로컬 포트 검사를 넣으면 에이전트 APK 버전이 올라가 기존 설치가 한 번 교체된다. (2) 도구 합치기(50 → 46)는 기존 에이전트 정의·저장된 대화와 이름이 달라진다. (3) 대화창 확인 절차를 MCP elicitation 으로 할지 데스크톱 자체 버튼으로 할지.

- 🟠3 "예전 SDK 와도 호환"은 새 호스트 + 옛 SDK 방향만 맞다. 새 SDK·에이전트는 헤더를 안 보내는 예전 데스크톱·MCP 를 403 으로 거부한다.
