## 2026-10-14 Flipper 대체를 SDK 없이 adb만으로 시작

- **무엇을 정했나**: 기본 기능(뷰 계층·Activity·Fragment·라이브러리)은 모두 adb로 한다. 네트워크·DB·Prefs만 선택형 SDK로 뺀다.
- **후보**: Flipper처럼 SDK 필수 / adb 기본 + SDK 선택.
- **고른 이유**: SDK가 필수면 남의 앱은 못 보고 내 앱도 release 빌드는 못 본다(개발 글 결정표).
- **누가 정했나**: 이승준(개발 글의 목표를 직접 세움).
- **버린 시도**: 없음.
- **근거**: `5dc4369`(v0.1.0), `2dd95fa`(v0.2.0 SDK).

## 2026-10-14 기기 안에 온디바이스 에이전트 APK를 올린다

- **무엇을 정했나**: Instrumentation + UiAutomation을 붙잡고 HTTP로 답하는 13KB 에이전트를 자동 설치한다. 실패하면 uiautomator로 돌아간다.
- **후보**: adb `uiautomator dump`·`dumpsys`만 쓰기 / 기기 안 에이전트.
- **고른 이유**: 뷰 계층 1.5~3초, Activity 확인 1~7초는 화면을 수십 번 읽는 에이전트에게 너무 길다. 에이전트로 0.03~0.3초, 한글 입력도 된다(개발 글, `591a14e`).
- **누가 정했나**: 이승준.
- **버린 시도**: adb만 쓰는 방식(지금은 대체 경로로만 남음).
- **근거**: `591a14e`, 개발 글 "2. adb가 너무 느려서".

## 2026-10-14 에이전트·SDK는 TCP 대신 유닉스 소켓 + UID 검사

- **무엇을 정했나**: 에이전트를 TCP 127.0.0.1:7912에서 `localabstract:droidlens_agent`로 옮기고, 접속 UID가 shell·root일 때만 받는다. SDK도 shell·root·앱 자신만 받는다.
- **후보**: TCP 포트 / 유닉스 소켓 + UID 검사.
- **고른 이유**: TCP면 같은 기기의 다른 앱이 UiAutomation 권한(화면 읽기·텍스트 주입)을 빌려 쓸 수 있었다.
- **누가 정했나**: 이승준(보안 리뷰 지적을 반영).
- **버린 시도**: TCP 포트, 에이전트 INTERNET 권한.
- **근거**: `f0c4abf`, 개발 글 "5. 검증". 이후 소켓을 다른 앱이 먼저 열면 연결하지 않게 보강(`71b19d0`, `2204ddc`).

## 2026-10-14 미러링은 scrcpy 서버 + WebCodecs

- **무엇을 정했나**: scrcpy v5 서버를 내려받아 H.264 스트림을 WebCodecs로 디코딩한다. 실패하면 스냅샷 모드로 돌아간다.
- **후보**: 스크린샷 반복(스냅샷 모드) / scrcpy 스트림.
- **고른 이유**: 고프레임(최대 60fps) 미러링.
- **누가 정했나**: 이승준.
- **버린 시도**: 없음(스냅샷 모드는 대체로 남음).
- **근거**: `87cb6a7`(v0.3.0). 서버는 SHA256 검증(`scripts/fetch-scrcpy.mjs`).

## 2026-10-14 에이전트가 직접 쓰게 MCP 서버를 내장한다

- **무엇을 정했나**: core 위에 MCP 서버를 두고 Claude Code가 같은 기능을 도구로 쓰게 한다. 앱에 단일 파일 번들을 넣고 설정 탭에서 `claude mcp add`까지 버튼 하나로 한다.
- **후보**: 기록 없음.
- **고른 이유**: Claude Code로 개발을 거의 다 하니 에이전트가 직접 검증하면 좋겠다고 봤다. Node를 따로 깔지 않아도 되게 Electron 안의 Node로 돌린다(개발 글).
- **누가 정했나**: 이승준(목표 "에이전트가 직접 쓰고 검증").
- **버린 시도**: 없음.
- **근거**: `5dc4369`(도구 28개), `7761c1b`(43개), 현재 50개.

## 2026-10-14 SDK 민감 정보는 기기 안에서 가린다

- **무엇을 정했나**: 네트워크 기록을 저장하기 전에 인증 헤더·토큰·비밀번호를 가린다. 키 이름은 부분 일치로, 문자열 안 JSON·GraphQL·multipart·XML까지.
- **후보**: 정확히 같은 키만 / 부분 일치 + 짧은 이름은 정확 일치.
- **고른 이유**: 정확 일치만 하니 `newPassword`, `fcmToken`, `jwt`가 그대로 남았다. 코드 리뷰가 실제로 컴파일해 돌려 보고 찾았다(개발 글).
- **누가 정했나**: 이승준(리뷰 지적 반영).
- **버린 시도**: 정확 일치. 처음 고친 정규식은 ReDoS가 있어 256KB 입력에 60초 넘게 걸렸다 → 되돌아가지 않는 수량자로 19ms 수준(`851f231`).
- **근거**: `0f6e098`, `16905d4`, `732abda`, `851f231`.

## 2026-10-14 macOS 임시(ad-hoc) 서명과 한 줄 설치 스크립트

- **버린 시도**: 서명 없는 빌드.

## 2026-11-19 QA 회차 실행·결과표 (#76)

- **무엇을 정했나**:
  - 회차는 `runs/<회차 id>/run.json` 하나에 TC 결과를 쌓는다. 스크립트 있는 TC 는 `qa_run_scripts`(CLI `qa run`)가 core 에서 바로 돌리고, 나머지는 에이전트가 `scenario_start(tc.run)` 로 돌려 `scenario_finish` 가 같은 회차에 적는다.
  - TC 에 스크립트를 이을 때 파일 sha256 을 함께 적고, 회귀 실행 때 같을 때만 사람이 허용한 확인 필수 동작을 누른다. TC 에 이은 스크립트는 `script_run(allowDanger)` 로 돌리지 못하게 했다.
  - 에이전트가 결과를 직접 적는 `qa_case_result` 는 건너뜀·막힘만, 이유를 꼭 받고, 실행해서 나온 통과·실패를 덮지 못한다.
  - 결과표는 HTML·CSV·JUnit 세 가지를 회차 폴더에 같이 쓴다. CSV 에는 입력값(`data`) 칸을 넣지 않는다.
  - CLI `qa run` 은 돌린 TC 가 실패·막힘이면 1, `--strict` 면 안 돌린 TC 가 있어도 1.
- **후보**: 결과를 시나리오 폴더에만 두고 결과표가 모아 읽기 / 회차 파일에 쌓기. 스크립트 변경 감지는 없음 / 수정 시각 / sha256. 에이전트 결과 기록은 모든 상태 / 건너뜀·막힘만. CI 실패 기준은 실패만 / 실패·막힘 / 안 돌림까지.
- **고른 이유**:
  - 회차 파일 하나면 데스크톱·MCP·CLI 가 같은 결과를 읽고, 같은 TC 를 다시 돌렸을 때 마지막 결과만 남기기 쉽다.

  - 통과를 에이전트 말로 적게 하면 근거(시나리오 리포트) 없는 통과가 생기고, 실패를 건너뜀으로 덮으면 결과표가 거짓말을 한다.

  - 글자 색 무리를 "가장 많은 색" 하나로 씨앗 삼기. 회색 글자 옆 검은 아이콘이 같은 색 선 위에 놓여 한 무리가 됐다. 배경에서 먼 절반에서 씨앗을 고르고, 씨앗보다 30% 넘게 진하면 다른 무리로 본다.

## 2026-11-26 QA 결과의 앱 메모는 코드 값과 한국어 글을 같이 남긴다 (#114)

- **무엇을 정했나**: 앱이 적는 결과 메모(수동 TC 건너뜀·다시 보기 표시·시간 제한·에이전트 시작 실패·결과 없이 끝남·스크립트 못 읽음·확인 필수 동작 안 누름)를 `note: {code, args}` 로 남기고 `detail` 에는 같은 뜻의 한국어 글을 그대로 둔다. 화면·내보내기는 core `qa-note.ts` 의 `qaResultMemo` 로 언어에 맞춰 보여 준다. 사람·에이전트 메모와 인자 속 오류 원문·시나리오 요약은 번역하지 않는다.
- **후보**: detail 을 영어로 바꿔 저장 / 코드 값만 저장 / 코드 값 + 한국어 detail. 옛 결과는 그대로 한국어 / 앱이 적던 문구를 되짚어 코드로.
- **고른 이유**: detail 만 읽는 CSV·JUnit·MCP 도구·옛 버전이 그대로 읽게 detail 을 남긴다. 옛 결과는 문구가 끝까지 같을 때만 되짚어 사람이 적은 글을 잘못 바꾸지 않는다. `note` 칸이 있는 회차 파일은 이 칸을 모르는 옛 버전(엄격한 스키마)이 읽지 못한다. 버전을 내리는 경우만 해당해 받아들였다.
- **누가 정했나**: 내 제안(사용자 위임 범위, "백로그 이슈 진행").

## 2026-11-26 TC 문구를 화면 지도의 실제 글자에 맞춘다 (#128)
- 문제: 에이전트는 TC 단계 글자와 지금 화면 글자를 맞춰 누를 곳을 고른다. 문서 표현과 화면 글자가 다르면 모델 판단에 기대고, 못 찾으면 스와이프·재시도로 시간이 든다.
- 결정: 자동 탐색으로 쌓인 화면 지도를 `graph_get format=labels`(화면별 버튼 글자·가는 길, json 보다 훨씬 작다)로 읽게 한다. TC 뽑기는 새 TC 단계에 지도 글자를 쓰고 다르면 notes 에 남긴다. TC 표를 옮길 때는 원문을 지키고 notes 에만 적는다. 실행 에이전트는 글자를 못 찾으면 지도를 먼저 보고 `graph_navigate` 로 간다.
- 고르지 않은 것: TC 뽑기 때 기기를 직접 열어 보게 하기. 플래너는 기기를 건드리지 않는 원칙을 지킨다. 지도가 없는 앱은 지금과 같다.

## 2026-11-26 문서 종류별 검증 갈래: TC 표는 모델 없이 원문 그대로 가져온다 (#129)
- 문제: TC 표(xlsx)를 넣은 계획에서 73개 중 69개가 원본과 같은 TC 였는데 모델이 69개를 한 줄씩 다시 옮겨 적었다. 시간이 들고, 옮기면서 글이 바뀔 수 있고, 원본에 없는 TC 가 섞여 구분되지 않았다. 기획서·Figma·TC 표가 검증하는 것도 서로 다른데 한 목록에 섞였다.
- 결정:
  - TC 마다 갈래(`track`: 기획 흐름·디자인 가이드·TC 문서)를 둔다. 칸이 없으면 kind 로 정해 옛 계획 파일을 그대로 읽는다.
  - TC 표는 core 가 넣는 순간 머리글 별칭으로 열을 찾아 원문 그대로 가져온다. 머리글을 못 알아보면 사람이 열을 고른다. 에이전트는 TC 문서 TC 의 원문을 바꾸지 못하고 요구사항·확인 필수 표시만 잇는다.
  - 계획에 TC 문서가 있으면 에이전트가 더 낸 TC 는 추가 제안(기본으로 고르지 않음)으로 따로 보이고 사람이 넣는다. 디자인 가이드 갈래는 Figma 문서의 검증이라 제안으로 돌리지 않는다.
  - Figma 는 기본으로 프레임마다 디자인 가이드 TC 만, 흐름 TC 는 보드에 흐름 정보가 있을 때만.
  - TC 문서가 덮은 요구사항에는 기획 흐름 TC 를 또 만들지 않게 덮임 표시(`coveredByTc`)를 저장 응답에 준다.
- 후보: (가) 지금처럼 에이전트가 옮겨 적기 / (나) 에이전트가 표를 열 매핑만 정하고 core 가 옮기기 / (다) core 가 열 이름으로 옮기고, 못 알아보면 사람이 고르기. 갈래는 (1) 새 칸 / (2) kind 에 값을 더함 / (3) 문서(source)로 추정.
- 고른 이유: (다)는 모델 호출 없이 바로 끝나고(직접 만든 73행 TC 표: xlsx 넣기 15ms·csv 3ms, 원문 일치 73/73) 원문이 바뀔 길이 없다. (나)도 모델이 끼어 결과가 흔들린다. 갈래는 kind(정상·예외·경계·디자인)와 다른 축이라 새 칸(1)으로 두었다. 문서로 추정(3)하면 TC 문서 TC 에 사람이 요구사항을 이어도 갈래가 바뀌지 않게 하기 어렵다.
- 누가 정했나: 사용자 요청("TC 문서를 넣으면 굳이 재판단해서 TC 를 새로 만드는 게 의미가 있나", "문서 종류별로 세분화 검증")에 따라 내가 설계(위임 범위).
- 고르지 않은 것: 추가 제안 TC 를 지우는 버튼. 제안은 고르지 않으면 실행되지 않고, 다시 뽑으면 바뀐다. TC 문서를 나중에 넣었을 때 이미 있던 에이전트 TC 를 제안으로 바꾸는 것(사람이 이미 본 TC 라 그대로 둔다).

- 리뷰 뒤 보강(같은 날): 기대 결과 열이 없는 표는 자동으로 가져오지 않는다. 별칭 '항목'·'단계'·'action'·'summary' 만으로 일정표·액션 아이템 표가 TC 표로 들어가면, TC 문서 TC 는 에이전트가 지울 수 없고 사람도 지울 함수가 없어 계획을 통째로 지워야 했다. 가져온 TC 를 되돌리는 기능은 이번 범위에서 빼고 따로 제안한다. 에이전트는 추가 제안 TC 를 고를 수 없다(`qa_case_update` 도 막음).
