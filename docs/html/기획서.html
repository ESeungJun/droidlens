#DroidLens 기획서

이 문서는 2026-11-05에 이미 구현·배포된 코드(v0.10.4), README, ROADMAP, git 히스토리, 개발 글(dev-post/03-droidlens/post.md)을 보고 거꾸로 정리했다. 구현된 기능을 사용자가 요구한 기능으로 본다.

관련 문서: 설계서 · 구현도 · 결정기록 · 로드맵

#한 줄 소개

Android 앱을 들여다보는 데스크톱 렌즈. SDK 없이 adb만으로 어떤 앱이든 화면·뷰 계층·화면 흐름·라이브러리를 보고, Claude Code 에이전트가 MCP로 기기를 직접 조작해 검증까지 한다.

#왜 만들었나

  • Meta의 Flipper가 2025년에 아카이브됐다. 앱 안에 SDK를 붙여 네트워크·DB·뷰 계층을 데스크톱에서 보던 도구였다.
  • Flipper는 SDK를 붙여야 해서 남의 앱은 못 보고, 내 앱도 release 빌드는 못 봤다(개발 글).
  • Claude Code로 개발을 거의 다 하다 보니 에이전트가 기기를 직접 보고 검증할 수 있으면 좋겠다고 봤다(개발 글).

#누가 쓰나

  • Android 개발자: 내 앱 디버깅(네트워크·DB·Prefs), 남의 앱 구조 분석.
  • QA·검증 담당: 말로 시나리오를 시키고, 통과한 흐름을 회귀 테스트로 쌓는다.
  • Claude Code 사용자: droidlens-verifier·droidlens-analyst 에이전트와 MCP 도구.
  • Android 개발자가 아닌 사람도 시작할 수 있어야 한다(기기 연결 도우미, 한 줄 설치).

#목표 (개발 글의 네 가지 기준)

  1. SDK 없이 어떤 앱이든 볼 수 있을 것
  2. 사람이 아니라 에이전트가 직접 쓰고 검증할 수 있을 것
  3. 안드로이드 개발자가 아니어도 시작할 수 있을 것
  4. 혼자서도 계속 굴러갈 것(릴리스만 올리면 설치·업데이트가 알아서)

#핵심 시나리오

  1. 남의 앱 분석: 기기 연결 → 앱 선택 → 라이브러리 탭에서 쓰는 라이브러리·난독화 여부 확인 → 뷰 계층 3D로 레이아웃 구조 확인 → 화면 흐름에서 자동 탐색으로 화면 지도 만들기.
  2. 내 앱 디버깅: debug 빌드에 SDK 추가 → 네트워크 탭에서 요청·응답 확인, 목 규칙으로 실패 상황 재현 → 앱 데이터 탭에서 Prefs·DB 편집.
  3. 에이전트 검증: Claude Code에 "로그인하고 설정에서 다크 모드 켜지는지 확인해줘" → droidlens-verifier가 기기를 조작하며 단계별 판정 → HTML 리포트 + 통과하면 YAML 스크립트 자동 저장.
  4. 회귀 실행: 저장된 스크립트 폴더를 데스크톱·MCP suite_run·CLI(droidlens-mcp.mjs run)로 다시 돌림 → 실패하면 종료 코드 1(CI용).
  5. 첫 사용: 기기가 없으면 기기 연결 도우미가 에뮬레이터 설치(Claude Code에 맡기는 프롬프트 포함)·실기기 연결을 안내.

#기능 목록

#구현됨

화면

  • 기기 화면: scrcpy 스트림 + WebCodecs 미러링(최대 60fps) 또는 스냅샷 모드, 탭·스와이프·롱프레스·하드웨어 키·텍스트 입력, 스크린샷, 녹화(최대 180초)
  • 뷰 계층: 스크린샷 ↔ 트리 양방향 선택, 속성·셀렉터, 깊이별 노드 수, Compose 추정, 3D 깊이 분해도
  • 화면 흐름: 앱별 화면 지도 누적(자동 탐색·직접 조작·시나리오 실행), 위험 버튼(결제·삭제·로그아웃·전송) 회피, 지정 동작으로 흐름 탐색, 경로 강조, 기록된 경로로 자동 이동, 지도 내보내기·가져오기

진단

  • 로그: 실시간 logcat(앱 PID 필터·레벨·검색), 최근 크래시
  • 네트워크(SDK): OkHttp 요청·응답, cURL 복사, 네트워크 목(응답·연결 실패·지연)
  • 성능: CPU·메모리(PSS)·초당 프레임, 버벅인 프레임 비율, 앱 시작 시간(콜드·다시 열기, 중앙값)

앱

  • 앱 데이터(SDK): SharedPreferences 조회·편집, SQLite/Room 브라우저와 SQL(쓰기는 명시 허용 시), 커스텀 이벤트
  • 앱 정보: 버전·SDK·권한·Activity, 실행·재시작·종료, 딥링크
  • 라이브러리: APK의 DEX·네이티브 lib로 라이브러리·프레임워크 탐지(시그니처 103개), 난독화 추정

테스트

  • 시나리오 검증 리포트(단계별 스크린샷·판정), 리포트 삭제·묶기
  • YAML 스크립트: 작성·실행·전체 회귀 실행, assert 11종(visible·notVisible·text·activity·package·network·pref·db·event·perf·noCrash), startup, 스크린샷 비교(matchScreenshot)
  • 에이전트 검증이 통과하면 조작·검사를 스크립트로 자동 녹화

연동·설정

  • 내장 MCP 서버(도구 50개), 설정 탭에서 claude mcp add --scope user 원클릭 등록, 에이전트 2종 설치
  • 앱 안 에이전트 대화창(이 컴퓨터의 Claude Code 로그인 사용, API 키 불필요)
  • 온디바이스 에이전트 APK 자동 설치·실행(상단 바에서 켜고 끄기)
  • 가상 기기(AVD) 목록·실행·종료, 기기 연결 도우미
  • 한국어·영어, 라이트·다크 테마
  • 한 줄 설치 스크립트(macOS·Linux), 앱 안 업데이트(달라진 조각만 받기)

#나중 (ROADMAP의 미완료 항목)

  • scrcpy 컨트롤 소켓으로 입력 지연 단축, 오디오
  • SDK: DataStore, Compose 트리 상세(recomposition)
  • 자동 탐색 개선: 스크롤 영역 탐색, 입력 폼 더미 값, 로그인 시나리오 프리셋 후 탐색
  • 결과 대시보드(실행 이력·성공률 추이), 스크립트 매개변수 주입
  • 버전 간 비교: 라이브러리 diff, 화면 그래프 diff, REA 연동

#범위 밖

항목 이유
타사 앱의 네트워크·DB·Prefs 앱 내부 정보라 SDK를 넣은 debug 빌드에서만 볼 수 있다(README 알려진 한계)
OkHttp가 아닌 네트워크 스택 인스펙터가 OkHttp 인터셉터 기반이다
iOS Android(adb) 전용 도구다
WebView·Flutter·게임 엔진 화면의 정밀 분석 접근성 노드가 적다(README 알려진 한계)
Appium 등과 동시 사용 UiAutomation을 하나만 잡을 수 있다. 에이전트를 끄면 된다

#지원 플랫폼과 배포 채널

  • 데스크톱: macOS(arm64·x64), Windows(x64·arm64), Linux(x86_64 AppImage)
  • 기기: Android 실기기·에뮬레이터(USB 디버깅). 에이전트 APK minSdk 24, SDK minSdk 21
  • 배포: GitHub Releases(공개 저장소 ESeungJun/droidlens), 한 줄 설치 스크립트, 앱 안 업데이트
  • SDK: JitPack(com.github.ESeungJun.droidlens:sdk / sdk-noop)
  • MCP 단독 파일: Releases의 droidlens-mcp.mjs(Node 20+)

#완료·성공 기준

  • SDK 없이 기기에 깔린 아무 앱에서 화면·뷰 계층·흐름·라이브러리를 볼 수 있다.
  • 에이전트가 MCP 도구만으로 시나리오를 검증하고 리포트·스크립트를 남긴다.
  • 저장된 스크립트를 CLI로 돌려 CI에서 성공·실패를 종료 코드로 받는다.
  • 위험 버튼은 자동 탐색과 MCP tap 모두 기본으로 누르지 않는다.
  • 릴리스 태그만 푸시하면 세 OS 설치 파일이 올라가고, 설치된 앱이 스스로 업데이트한다.
